# Company sign-in and catalogue publishing UI

Build on merged #74/#75. Add a Company catalogue window from the File menu; CAD remains available without sign-in. Use MSAL Browser single-tenant delegated PKCE popup flow, silent API token acquisition and a separate redirect bridge page. Build-time public tenant/SPA/API GUIDs configure authentication; no secret, token paste, simulated role or live account is shipped. Same-origin API only. Missing config gives an IT setup message.

API `/me` determines identity/roles. IT can author master rules and stocks; senior designers can author scalar cabinet recipes pinned to installed starter layout and published company rule versions. Forms expose every supported field with optional product inheritance. Stocks have name/thickness/grain/edge use; supplier rates are excluded. Saving returns validated content, revision and digest. Only creators edit/submit/withdraw. A different senior designer publishes/requests changes for products; IT publishes rules. UI gating aids navigation; server authority is unchanged.

Submission and publication always operate on the exact displayed saved revision. Dirty edits prevent submit. A confirmation shows ID/base/new version/revision/digest/pins before publication. A 409 disables commands until an explicit reload; no automatic retry/rebase. An uncertain network outcome also requires reload. Session expiry/401 clears private data and requires explicit sign-in. Sign-out clears private data immediately, invalidates in-flight responses, and clears MSAL cache. Switching accounts requires sign-out/sign-in; no default first cached account. Closing the window discards unsaved form values; warn before closing dirty forms.

Published history shows immutable content, author/approver/time/digest; draft history shows audit notes and actors. Creating a subsequent version copies only editable content from a published version while retaining the company ID. No CAD adoption, deployment, production release, layout/hardware/drilling authoring or version withdrawal is added.

Verification: auth/config/client unit tests; UI tests with injected transport/session for saved revision, self-approval, conflicts, stale responses, forms and confirmation. Browser test for unconfigured entry and callback build. Full repository gates and deliberate mutations of principal/revision/session guards. Live Entra acceptance remains an IT deployment check.
