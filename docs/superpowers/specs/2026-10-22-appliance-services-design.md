# Appliance bays and service openings

Approved scope: 25 appliance-bay tasks and 25 service/ventilation tasks from the conversation. Add cabinet tabs for Appliance Bays and Service Openings. Existing Materials & Edgebanding commit is retained as the branch base; neither batch is published by this task.

Bays are optional Scene recipes keyed by stable bay/cabinet/leaf-opening IDs, with category/name, body W/H/D, five installation clearances, horizontal reference/offset, elevation and signed front recess. Physical opening rectangles intersect face-frame access with structural openings; usable depth follows the existing back/front rules. Pure resolution supplies local body and reserved boxes, required/available sizes and stock-envelope interference with real cabinet boards, drawer boxes and other bays. Touching is allowed. Arbitrary board rotations use conservative cabinet-space bounds; cuts do not subtract from fit envelopes. Bays are fit/planning envelopes rather than manufacturing parts and never resize/delete construction. Valid recipes may be saved with prominently reported fit issues; missing references and malformed data cannot be newly accepted. Source changes recompute diagnostics; no ghost stock/BOM/STEP bodies.

Service recipes live on BoardPart and use existing rectangular/circular machining semantics, plus ±Z broad-face entry, bounded repeated slots, minimum web and optional bay association. Positions are board-local edge/centre references. The final pipeline pass resolves panel dimensions after joints and updates only its own stable cut IDs. It checks positive stock, depth, edge margins, web between features and existing machining (conservative board-local boxes, including bounded hole arrays). Unsupported mitres or unbounded arrays decline rather than claim assessment. Invalid rebuilds retain complete last-valid service cuts and surface diagnostics. Removal of a valid recipe removes its own cuts only. Reconcile/merge passes preserve recipes; duplicates retain fixed cut copies without live service ownership. Normal cut tools cannot modify recipe-owned cuts. No supplier-certified appliance, radiused slot ends or ventilation-performance model is implied.

Both editors stage, preview and accept from exact whole-Scene signatures. Acceptance recomputes and ignores cached candidate geometry; stale/no-op/invalid commands cannot create history. Per-workspace apply is one undo entry. Format 36 persists optional bays and service recipes; legacy files lack both. Raw/current validators enforce structure and count bounds while permitting saved broken references for repair. Regression coverage includes pipeline order, ownership, duplication, fit, panel resize/freeze/recovery, clash detection, file boundaries, undo, UI and browser paths; guard mutations must fail by assertions.
