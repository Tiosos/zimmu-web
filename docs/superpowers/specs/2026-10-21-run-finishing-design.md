# Run plinths and splashbacks

Extend the existing continuous run-board lifecycle to vertical plinths and splashbacks, with a separate Finishing workspace. Reuse runWorktop metadata/pipeline/acceptance as the common board link implementation, adding an explicitly versioned profile rather than a second almost-identical ownership system. Worktop recipes remain version 1 with no profile; vertical profiles require version 2 and project format 34. Older builds reject the new recipe instead of regenerating a vertical panel as a worktop.

The 25 tasks are workspace, profile choice, explicit membership, anchored-run selection, parent/orientation validation, plinth front/base alignment, splash rear/top alignment, gap allowance, left/right extensions, height, toe-height following, vertical clearance, plinth setback, rear clearance, materials, stock/custom thickness, grain, name, dimensions/area/member gaps, three projections, real board/undo, linked following, edit/detach/delete, persistence/invalid-link diagnostics.

Plinths require toe-kick or ladder bases and aligned occupied fronts/base planes, not equal cabinet tops. Toe-height mode follows the minimum member toe-kick height minus bottom clearance; custom height must fit that same available height. Setback is measured from the occupied front and the complete thickness must fit the shallowest member depth. This is a rectangular fit envelope, not collision/attachment certification.

Splashbacks require aligned occupied fronts/rears and tops; differing rear lines need separate panels. They stand behind the common rear with optional rear clearance, and above cabinet top with a vertical gap. Left/right extensions remain explicit. Vertical panels use orientedPanel thickness axis Y composed with the reference cabinet transform into the common parent; decompose to XYZ only for vertical profiles, preserving legacy worktop transforms exactly.

Only matching profile families may be edited in their workspace; a worktop with cutout recipes cannot become a vertical panel. Worktop machining eligibility rejects vertical run profiles, and file validation rejects incompatible saved recipes. Generic independent cuts/edges/cosmetics remain owned by normal board tools. Linked width/material/placement updates reuse stable IDs; invalid geometry freezes last valid board with diagnostics; all sources removed releases link. Direct owned-property edits and duplication produce fixed boards through existing link lifecycle.

UI supplies explicit preview, reset/cancel, stock/custom, grain/name, member list, projections and linked edit/manage controls. Stale geometry/material/ownership changes invalidate preview, mesh-only changes do not. Save/add/delete/detach each one undo step with profile-specific labels. No new dependencies, board stock, joints or corner geometry. User can choose alternative material-overrides batch before dependent implementation; otherwise proceed with recommendation.

Verification: pure profile validator/geometry/bounds/transform/parent/gap/height tests; linked freeze/recovery/identity/override preservation; old recipes unchanged; v34 round-trip and invalid-profile combinations; UI/hook/browser workflows and legacy worktop regressions. Mutation-check guards from green baseline with source backups/restoration. Required typecheck/lint/full unit tests, CAD/catalogue builds and isolated browser before local commit.
