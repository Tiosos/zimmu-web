# Fit a cabinet run

Extend the existing Layout tools with a target-span sizing workflow. Basic multi-cabinet movement/order/spacing already exists; this batch adds constrained width allocation and coordinated resizing/placement, not another general layout engine.

The 25 tasks: dedicated fit workspace; selection; earlier/later/reverse order; target span; start/end reserves; inter-cabinet gap; X/Y axis; positive/negative direction; near-edge alignment; fixed width; per-cabinet minimum/maximum; equal/proportional allocation; bounded redistribution; infeasibility diagnostics; destination construction/drawer validation; explicit anchor detachment; plan preview; width/position/reserve comparison; overlap diagnostics; guarded one-step apply/undo.

Only upright co-oriented quarter-turn cabinets can form a straight run. Their local width must align with the chosen parent axis (X at 0/180 degrees, Y at 90/270 degrees). All selected cabinets share one parent. Keep the original first cabinet occupied near boundary as target origin; start reserve shifts the first cabinet into the span. Negative direction measures backwards from its original far boundary. Align the perpendicular occupied near edge to the first cabinet and preserve individual Z positions. Rotations remain unchanged. Reserves are empty spaces, never generated filler boards or claimed site measurements.

Allocation subtracts reserves and n−1 gaps from the positive finite target. Fixed entries retain current width. Flexible entries have positive finite min/max and min <= max; distribute equal widths or proportions of current widths using a bounded weighted solution, clamping and redistributing until all fit. Final sum tolerance 1e-6 mm; no silent rounding or automatic relaxation. Require at least two distinct cabinets, at least one flexible entry. Limit 100 selected cabinets to bound work.

Before geometry mutation use constructionErrors on each candidate width, retained parts/overrides and drawer parameters. Pipeline regenerates dependent geometry/finishing/worktops and anchored followers. Compare desired widths/positions after reconciliation; reject if a rule changes them. Use existing placement overlap assessment for sibling occupied envelopes. Warnings permit intentional overlaps; they do not assess room walls or door swing. Use frontsSignature for material/part/drawer/catalogue/rule/placement staleness. Acceptance rebuilds from current scene/draft, never trusts a caller's proposed scene. One discrete history label. Preview stale after external changes; mesh-only changes ignored.

UI: select/order rows with fixed/min/max controls, target/reserve/gap fields, allocation/axis/direction choices; reset/cancel, explicit preview, plan with width/position table and fit equation; apply only validated changed preview. Leaving tab discards draft. Existing Layout editor remains default, fit reached via a workspace switch.

Tests: pure allocation bounds/sums/permutations and input guards; actual pipeline/drawer/anchors/geometry integration; UI draft/stale/cancel/accept/selection; hook undo/redo; browser end-to-end plus existing Layout/Construction regressions. Mutation-check guards after green baseline with exact backups. Full required checks before local commit. Build on prior local preset commit ff03fe8 so the next PR can include both batches.
