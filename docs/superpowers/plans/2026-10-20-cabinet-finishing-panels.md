# Cabinet finishing-panel implementation

Spec: [design](../specs/2026-10-20-cabinet-finishing-panels-design.md). Notes: [implementation notes](../notes/2026-10-20-cabinet-finishing-panels-notes.md).

1. Implement a pure finishing draft/preview builder. Use local slot-based occupied bounds, `orientedPanel` and source-cabinet parenting; emit no schema fields or regeneration role. Enumerate seven supported panel types and keep names, stock/custom thickness, grain, four overhangs, height, filler width, clearance and setback explicit. Reject malformed choices, missing stock, invalid source geometry, nonpositive dimensions, negative offsets, plinth depth excess, finite-input overflow and non-finite transformed corners.
2. Copy preview inputs and signature source geometry/materials/parts while excluding meshes and unrelated hardware. Acceptance rejects errors, absent preview board, stale sources and colliding/empty IDs, rebuilds against the current scene, then appends one board with a fresh ID. Preserve unrelated current scene data; never trust cached preview geometry.
3. Add a Finishing tab and scene callback through CabinetEditor/App. Use normal reconciliation for one `Add finishing board` undo step. Keep surgical changes to existing large files. Exclude the editor from projection export buttons.
4. Build type/material/thickness/grain/dimension controls and expose only applicable dimensions. Every edit invalidates preview. External geometry changes require reset; successful Apply adopts the reconciled source signature without leaving a stale draft. Reset/Cancel/fit/type changes reset staged inputs. Preview actual existing cabinet parts plus the candidate through the shared Front/Top/End projector; show board-size/material/grain/area/local-extents summary and fixed-size/manual-part behavior.
5. Unit-test all seven actual oriented bounds, occupied front/back offsets, world attachment under cabinet rotation, material filtering, custom thickness, source/draft isolation, ID safety and rebuild behavior. Verify regeneration preserves manual boards, file parsing accepts them, and existing manufacturing/cutting-list outputs consume them. UI tests cover all controls, three SVG projections, stale/mesh/reset/cancel and rejected/successful Apply. Scene-hook test keeps sizing/addition undo steps separate and retains fixed panel sizing on later cabinet resize.
6. Add Chromium workflows for sized-cabinet worktop preview/add/undo/redo/fixed sizing and custom filler plus invalid plinth rejection. Wait for debounced cabinet geometry before entering the editor. Mutation-test guards after green baseline, back up/restore source files and inspect assertion failures. Regenerate structure reference, run full units with local networking enabled, then typecheck/lint/builds and browser workflows without overlapping source edits or heavy validation jobs. Record exact outcomes and commit to the feature branch.

Alternatives considered: persistent parametric finishing recipes would require schema migration and ownership/update/delete semantics; ordinary manual boards satisfy this batch using established editing/manufacturing paths. Room-wide multi-cabinet worktops, cutouts and hardware machining remain independent future features. Do not infer panel ownership from names, silently replace boards, auto-resize accepted panels or claim physical collision checks from projection previews.
