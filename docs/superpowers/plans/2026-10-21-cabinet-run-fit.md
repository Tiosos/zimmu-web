# Run fit implementation plan

Spec: ../specs/2026-10-21-cabinet-run-fit-design.md
Notes: ../notes/2026-10-21-cabinet-run-fit-notes.md

1. Implement runFit draft/entry types, initial rows from sibling cabinets, strict number/enumeration/selection/parent/orientation guards. Pure width solver uses bounded weighted bisection with a tight sum check; equal weights or positive current width weights. Fixed entries remove space from flexible budget. Reject impossible target before division. Test feasible/exact bounds/zero gaps, redistribution, all fixed, oversubscribed/undersubscribed, nonfinite/blank/negative, mixed parents/rotations/missing IDs.
2. Preview resolves current anchor positions first, calculates widths and occupied bounds, validates all candidate constructions against retained drawers/overrides, detaches selected anchors only on explicit choice, arranges positive/negative X/Y by occupied bounds including fronts/frame/back. Run pipeline once with all resized/positioned cabinets; recheck intended dimensions and positions after reconciliation. Assess sibling overlaps via existing previewLayout, retaining unselected followers. Build comparison rows/fit dimensions. Accept checks frontsSignature and regenerates from stored draft, never uses cached scene.
3. Add RunFitEditor and small Layout workspace wrapper. Isolate fit controls from legacy Layout label/tests. Selection starts fresh min/max/fixed defaults and clears preview; all edits/reorder clear preview. Stale model retains draft and requires reset; successful apply handles reconciled scene refresh. Display reserves as dimensions only; show warning semantics and frame coordinates plainly. Preview PlanView read-only, scoped to siblings.
4. Wire pure acceptance callback through useScene/App/CabinetEditor with one history label. Hook test verifies aggregate undo/redo, prior edit separation and stale/noop rejection. Component tests cover input validation, selectable/fixed rows, preview clearing, apply failures, resets and external changes.
5. Document workflow/constraints/reserves, write tests first alongside each seam, run focused green then targeted assertion mutations with exact backup/restore. Freeze code during complete unit/browser runs. Required typecheck/lint/full unit suite, both production builds, isolated browser new workflow and related existing regressions. Regenerate architecture trees and commit locally. No PR/push absent user request.

Alternatives: repeated single-cabinet updates rejected (multiple undo steps/intermediate invalid geometry); arbitrary angled runs rejected (AABB widths not true cabinet widths); generating filler boards deferred (reserves do not define panel depth/material). No server catalogue changes or dependencies.
