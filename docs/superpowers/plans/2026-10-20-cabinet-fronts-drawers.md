# Fronts & Drawers implementation

Spec: [25-task design](../specs/2026-10-20-cabinet-fronts-drawers-design.md). Notes: [implementation notes](../notes/2026-10-20-cabinet-fronts-drawers-notes.md).

1. Resolve structural leaf openings with the existing geometry/ownership chain. For explicit frame layouts, enumerate leaf zones and their physical rectangles instead. Use `(sectionId, openingId)` identities so drawers, front roles and selection agree; retain one logical target for structural pair-stile doors. Lock targets with detached fronts, detached drawer components or detached box boards.
2. Implement independent staged front-choice and drawer-parameter maps. Validate selections and commands before returning a new draft. Front removal/type changes clear obsolete drawer patches. Drawer commands require all selected targets to carry a staged/current drawer front; validate family, height, offset and stock material. Switching to undermount drops staged side-mount offsets.
3. Preview by applying section/zone front changes, preserving catalogue overrides, running the pipeline to create new drawers, applying selected drawer patches, then rerunning the pipeline. Validate complete five-board boxes, explicit height bounds, front emission and finite positive board geometry. Use cabinet-local generated bounds to reject positive-volume intersection of selected boxes with modeled section shelves while allowing boxes below shelves. Do not remove shelves or manual obstacles.
4. Compare board rows by opening/role rather than random preview-created IDs and tally hardware from emitted machining. Copy staged inputs into previews and sign geometry, ownership, drawer parameters and rules/catalogues while excluding meshes and unrelated hardware. Acceptance rejects stale/invalid/no-op proposals and rebuilds from the copied draft against the latest scene. Scene-hook callback records one `Apply fronts and drawers` history step.
5. Add a wrapping cabinet tab list and the workspace. Selection/filter changes retain edits and invalidate Preview. Provide seven front commands and explicit Stage buttons for drawer settings, plus staged rows, read-only front projection, hardware and board summaries. Reset/Cancel discard drafts. External geometry changes require Reset; successful Apply adopts the reconciled scene. Keep edits to existing large files surgical and exclude the tab from drawing export buttons.
6. Unit-test seven front commands, multiple openings, independent frame zones/pair stiles, new and existing drawers, materials/families/heights/offsets, shelf fit, ownership locks, metadata preservation and stale/no-op/tampered acceptance. UI tests exercise selection, filters, controls, previews, summaries, errors and reset/apply transitions. Scene-hook test proves separate sizing and batch undo/redo. Chromium workflows cover actual drawer creation and multi-opening invalid-fit/cancel behavior.
7. Establish a green baseline, back up sources, deliberately mutate guards and inspect assertion failures, then restore and compare copies. Regenerate the structure reference. Run full units with local networking, followed by typecheck/lint/builds and browser checks without competing heavy jobs or source edits. Record exact results and commit on the feature branch.

Alternatives: front changes by structural section alone fail independent frame zones; ID-based row comparisons falsely report recreated drawers; accepting cached scene snapshots can overwrite current unrelated metadata. Hardware geometry and vendor tables remain unchanged. Parametric finishing panels, mounting/reveal changes, automatic shelf removal and arbitrary obstacle clearance are outside this batch.
