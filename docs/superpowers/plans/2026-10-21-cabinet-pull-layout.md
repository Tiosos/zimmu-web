# Cabinet pull layout implementation

1. Add browser-safe PullSpec validation and geometry helper with finite/positive dimensions, bounded offsets, circle containment and hinge-cup overlap checks. Guard tests cover malformed saved settings and physical board-space holes (including mirrored leaves and rotated cabinets).
2. Add optional BoardPart.frontPull and regenerate cuts inside the existing carcase pass using actual RoleSpec.panel and resolved FrontCell hinge. A FrontSpec extension was considered but would unnecessarily couple product-specific drilling to structural section/library schemas; board metadata already has stable front identity and supports individual paired leaves. Decline invalid pattern geometry and expose diagnostics rather than freezing cabinet geometry or keeping stale machining. Remove metadata for ineligible front types; preserve detached/manual boards.
3. Extend hardware definitions with dimension-specific generic pull names and deterministic trailing key order. Count one physical handle from one matching emitted array, not hole count or requests. Update grouped BOM/library names and verify pricing/CSV, unchanged hinge/runner counts, invalid and removed pattern exclusion.
4. Add pure target/stage/preview/accept functions. Reuse existing front resolving and signatures, extend signature with pull metadata. Revalidate IDs, ownership, settings, scene geometry, complete emitted pattern and no-op state. Preserve unrelated scene metadata on acceptance.
5. Wire onApplyPullPreview through scene history, App and CabinetEditor. Add Hardware tab and prevent projection export buttons on it. UI lists physical fronts, locks manual fronts, offers five selection actions, editable form with load-existing, staged settings/removal, reset/cancel and preview/apply. Changing form or selection invalidates candidate but retains staged edits. Stale scene requires reset. Show actual hole centres, quantities and Front/Top/End views.
6. Increment project schema to 30, validate legacy/current BoardPart metadata, update version pin and retain old-board behavior. Add focused unit, UI and history tests plus browser flow. Mutation-test new guards with scratch backups and inspect AssertionErrors before restoring. Run typecheck, lint and complete unit suite sequentially, then both builds and browser regression workflows. Update guide, notes, structure index, inspect changes and commit locally on claude branch. No PR/merge until asked.
