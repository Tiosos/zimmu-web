# Keycloak migration implementation plan

Spec: ../specs/2026-10-02-keycloak-catalogue-design.md
Notes: ../notes/2026-10-02-keycloak-catalogue-notes.md

1. Create an API feature worktree from merged main; leave #76's browser work isolated. Read existing verifier, store identity assumptions, HTTP fixtures and configuration before editing.
2. Replace Entra settings with a fixed Keycloak realm issuer, API client audience, authorised SPA client and stable company ID. Validate issuer URL (HTTPS except loopback; no credentials/query/fragment), realm path, distinct nonempty client IDs, durable database and absolute bindings-file path. Keep Principal DTO stable for audit/SQLite compatibility.
3. Add bounded strict JSON bindings loader. Require exact issuer/company, GUID staff IDs, nonempty opaque subject keys and one subject per staff ID. Reject unknown fields/malformed JSON/unreadable file. Evaluate bindings on every request for immediate unbinding. No email linking or user-controlled claim mappings.
4. Verify signed RS256 tokens with static trusted certs endpoint and exact issuer/audience. Require exp/iat/sub/scope/typ/azp; limit access to configured SPA and Bearer API tokens. Read only allowlisted API-client roles. Resolve bound subject to canonical staff ID; return a scoped reader for no authorised role. Ignore arbitrary tenant/staff/email/role claims.
5. Update signed-token helpers, HTTP tests and config tests. Add migration test preserving the existing actor ID so a migrated author remains unable to self-approve. Add tests for absent/removed/reassigned/duplicate bindings, forged company claims, realm and foreign-client roles, bad issuers and ID/service tokens.
6. Document Keycloak realm/client/scope/audience/client-role configuration, disabled public signup/service/direct grants, MFA, exact redirects/origins and IT identity linking. Use stable IDs for new and existing deployments; protect/atomically replace the file and never rewrite SQL evidence. Keep historical Entra specs as history, clearly superseded by this spec.
7. Run focused tests green, deliberate guard mutations with byte-for-byte backups/restoration, typecheck/lint/full unit suite/browser and server builds/diff check. Update architecture/notes. Commit, upload and verify exact remote tree. Open draft API PR against main.
8. Restack #76 on the API branch. Replace MSAL with keycloak-js and separate catalogue window init before React. Use standard PKCE S256, in-memory tokens, explicit login, updateToken, local token clearing before logout and session generations. Restore authorised catalogue view after SDK callback through server /me; never redirect the CAD window. Remove MSAL bridge and Entra active setup.
9. Test UI sign-in readiness/token refresh/sign-out races, configuration, callback cleanup and unopened CAD preservation. Re-run all gates, mutation-test new session guards, update PR #76 title/body/base and inspect both CI/E2E. No merge or live deployment in this task.
