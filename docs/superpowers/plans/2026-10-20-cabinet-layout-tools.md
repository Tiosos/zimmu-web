# Multi-cabinet layout implementation

Spec: [cabinet layout tools](../specs/2026-10-20-cabinet-layout-tools-design.md). Notes: [implementation notes](../notes/2026-10-20-cabinet-layout-tools-notes.md).

1. Create `layoutTools.ts` with an ordered ID selection, independent position snapshots and explicit detach flag. Resolve existing anchors before initializing positions. Validate unique existing sibling carcases, finite positions and every sibling's geometry/bounds through the existing placement validator. Return errors without mutating input.
2. Implement accumulated move/run/align/distribute operations. Translation adds finite offsets on all axes. Run keeps the reference's occupied minimum and uses actual extent plus nonnegative gap. Align matches an edge or centre to the fixed reference and preserves other axes. Distribution sorts on the chosen occupied minimum and keeps outer cabinets fixed; compute free span minus all extents and divide by N−1. Reject short selections, insufficient span and overflow. Sort selection using staged occupied minima; stable ties retain order.
3. Add preview signature and guarded acceptance. Copy the draft independently; reject stale signatures, errors and no-op previews. Reconstruct against the latest scene to retain hardware/metadata and derive unselected followers. Never trust cached proposed geometry. Keep material-slot bounds consistent with existing placement semantics; no schema, persistent draft or anchor-creation changes.
4. Add Layout tab to `CabinetEditor`; wire a new scene callback through App. Normal reconciliation records exactly one `Apply cabinet layout` undo step. Exclude the tab from drawing exports. Keep old large files surgically edited.
5. Build sibling selection, selected-order controls, reference label, staged positions, XYZ offset inputs, gap input, nine align buttons and three run/distribute buttons. Selection changes reset positions; reordering preserves them. Invalidate preview on all draft/control changes. Require reset after external geometry changes and retain preview across mesh-only updates. Show lock/error/noop/rejected-apply states and read-only plan/3D overlap warnings. Reset and Cancel never apply.
6. Test actual envelope outcomes for three run axes, nine alignments and three distributions, including rotated/applied-back and unequal-size cases. Assert off-axis invariance, endpoint stability, accumulated operations, independent snapshots, latest metadata, detachment/followers, positive-volume overlap and atomic invalid/stale/no-op rejection. UI tests cover controls and invalidation; scene hook tests verify separate sizing and layout undo/redo.
7. Exercise real Chromium workflows for three-cabinet run/sizing/undo/redo and multi-selection reorder/move/overlap/cancel. Wait for debounced sizing geometry before staging. Do not edit sources during browser validation.
8. Establish green focused baseline before deliberate mutations. Back up sources outside the repo, replace each guard, inspect expected assertion failures, and restore/compare. Tighten assertions if a downstream guard masks the intended failure. Once restored, run full unit suite, typecheck/lint, both production builds, targeted browser workflows, diff whitespace validation and structure regeneration. Record exact outcomes in notes and user-facing report.

Alternatives: worktops/fillers and hardware controls require independent part/manufacturing semantics; keep them for later batches. Persistent multi-cabinet anchors would change future edit behavior; this batch performs explicit one-time placements. Room-global transforms and physical door/obstacle clearance belong to the existing room assessment rather than parent-frame cabinet layout.
