# Cabinet placement tools

- Next fifteen tasks form a Placement tab: staged coordinates, two quarter turns, rotation reset, six edge alignments, three centre alignments and preview/apply. Reuses slot-based carcaseWorldBounds, resolvePlacement and PlanView in the shared parent frame.
- Alignment cannot reference self, a different parent or a transitive anchored follower. Follower traversal tracks visited identities to terminate on existing invalid cycles. Explicit detach is required for staging an anchored cabinet's free placement.
- Preview recomputes anchored followers and compares sibling occupied envelopes in all three axes, with a small touching tolerance. Warnings allow Apply because arbitrary-rotation axis-aligned boxes are conservative. Existing room/production assessments remain separate.
- Signatures capture component geometry/transforms/anchors and material definitions, excluding meshes. Acceptance rechecks the current scene and reconstructs the proposal from an independent draft snapshot, retaining current hardware and unrelated scene metadata. A dedicated scene-hook callback gives discrete undo/redo and refuses stale/no-op proposals.
- Twenty-two deliberate mutations produced expected assertion failures for parent/follower filtering, finite inputs, detachment, turns, target eligibility, alignment/geometry validation, overlap volume/touching, snapshot isolation, stale/error/no-op acceptance, proposal rebuilding, UI locks and history labels. Restored every source from backups and compared before final validation.
