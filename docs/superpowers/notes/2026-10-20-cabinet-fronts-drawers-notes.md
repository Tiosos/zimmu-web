# Fronts & Drawers implementation notes

- Starts from main `87fad25` after PR #146. User chose Fronts & Drawers; all 25 tasks were listed before implementation.
- Independent face-frame zones require their own front owner IDs. Structural pair-stile doors remain one logical front selection. A section-only editor would silently edit the wrong front for explicit frame layouts, so both ownership forms are supported.
- Detached front/drawer/box parts lock their opening in this workflow. Ordinary manual finishing boards remain untouched. Uses existing runner geometry and its documented confidence limits.
- Fit must account for the existing adjustable shelf in Base 600. Uses the shared cabinet-local box projector to compare modeled section shelves with the selected drawer's outer envelope. A low box can fit below a shelf; a full-height box is rejected. Manual obstacles and unmodeled installation clearance remain outside this check.

Acceptance rebuilds rather than trusting temporary preview UUIDs. Board deltas use opening/role identities; detached/released drawers use their component identity.
- Runner-offset edits are side-mount only. Switching staged family to undermount discards the staged offset instead of carrying an inapplicable setting into preview. Existing model defaults remain unchanged.
