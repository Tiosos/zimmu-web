# Resume working-design reviews from JSON

- Adds a browser-local file chooser for existing version-2 change report JSON. No report schema or project-file change is needed; version-1 reports have no review and are rejected explicitly. HTML remains printable only.
- The import boundary parses unknown JSON, enforces a 64 MiB UTF-8 limit and supported metadata, then regenerates the report from captured baseline/current source. Full before/after records, counts, changes, source-section coverage and limitations must match. Object key order is ignored; comparison array order remains significant.
- Review references, notes and booleans pass the existing draft validator. Labels/categories, recomputed progress, self-declared identity and unrecorded formal approval must also match exactly; unknown fields in review records/findings and the root are rejected. Review-entry order may differ; output is restored to current coverage order. A historical appVersion is accepted when comparison content is still identical.
- Import and download share one operation lock. File size is checked before reading, and the chooser resets its value for same-file retry. The importer captures baseline metadata before awaiting hashes. UI context/edit generations prevent a late read/hash result from overwriting a changed comparison or newer draft; equal-content rerenders remain valid.
- Replacement confirmation occurs only after validation and only for uncopied edits. Failure/cancellation preserves notes and the saved checkpoint. Successful resume marks the restored draft copied because the selected JSON already contains it. The existing close/unmount guard cancels delivery.
- Tests cover round-trip restoration/re-export, altered hashes and comparison data, identity/approval/progress claims, coverage errors, size/read failures, cancellation, retry and asynchronous context/edit races. The browser flow closes/reopens the comparison, resumes a saved report, rejects a stale file without losing edits, retries the same filename and exports restored notes in JSON/HTML.

- Regression found during review: JSON.parse accepts an overflowing numeric token such as 1e999 as Infinity, and JSON serialization maps that to null. Incoming numbers are now checked for finiteness in the parse reviver so a fabricated overflow cannot masquerade as an expected null field during canonical comparison. The regression test failed before this fix.

- Final validation: 125 tests across eight focused/integration files passed; the expanded Chromium close/reopen/resume/stale-file/retry/re-export workflow passed; type checking, lint and production build passed.
- Mutation checks: removing counts/changed-definition comparison made both altered-data tests fail; removing the newer-edit generation guard made the queued-edit test fail by overwriting its reviewer. Both safeguards were restored before passing verification.
