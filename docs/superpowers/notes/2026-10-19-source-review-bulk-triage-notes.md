# Source review triage and bulk actions

- Implements ten follow-ups to PR #138: group filter, part/hardware filter, note-presence filter, alphabetical part ordering, previous pending part, first/last pending part, complete visible pending findings, reopen visible reviewed findings, undo last bulk action, and remembered new view settings.
- Finding group and note filters cover every finding category. Item kind, classification and change type leave global source and limitation findings in scope. Summary ordering/search controls affect part navigation without silently narrowing the main findings.
- Bulk actions target unique visible coverage references, confirm the exact count, preserve all notes and hidden findings, and use the existing edit/autosave path. Undo is an in-memory exact-draft checkpoint; later review edits/resume or comparison changes invalidate it, while view changes/downloads preserve it. This prevents undo from overwriting newer review work.
- Preference additions are optional in legacy records. Invalid enums are rejected; absent fields use existing defaults. No report schema or draft storage changes are needed.
- Regression verification: targeted tests passed before mutation checks. Deliberate mutations to group/kind/note filtering, natural sorting and ID ties, reverse part navigation and completed-part skipping, bulk scope/confirmation/busy controls, undo draft/context guards in the initial version and each new preference enum caused assertion failures. The initial two-part reverse-navigation test could not distinguish directions; expanded it to three parts and confirmed the mutation then failed. Source files restored from scratch backups and patterns verified after each mutation.
- Lint rejected reading the async context-version ref during render for undo availability. Replaced that check with conditional checkpoint invalidation when the current draft changes, following the existing view hook’s guarded render-state pattern. This clears stale undo before commit and prevents switching back to a prior source pair from reviving it. The browser test now temporarily removes its existing auto-accept dialog listener to exercise cancellation explicitly.
- Final verification: 189 unit-test files passed (3,343 passed, 10 skipped); 76 focused UI/autosave/preferences tests also passed after the undo-state adjustment. The final undo-expiration guard was separately mutated: switching back to the original source pair incorrectly reenabled undo and the test failed; restoring the backup passed. Typecheck, lint, production build and the expanded Chromium release-review workflow passed. Browser coverage includes cancelling/confirming bulk reopening, undo, bulk completion and remembered triage settings. Whitespace checks passed.
