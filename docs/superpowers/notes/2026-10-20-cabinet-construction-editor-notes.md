# Cabinet construction editor

- Implements fifteen construction tasks as a staged Construction tab, complementing the existing direct sidebar controls. Coordinated changes can cross invalid intermediate states (for example enable a frame and choose half-overlay together) without committing those states.
- Pure draft helpers retain numeric input strings and parse finite/positive/non-negative values before geometry. Canonical opening/drawer validation uses actual role overrides and retained drawer components. No new cabinet format or geometry semantics.
- Member edits preserve independent frame layouts; removing the frame removes them. UI text discloses this before applying. Frame defaults come from DEFAULT_FRAME, rather than another set of construction dimensions.
- Summary counts come from carcaseRoles and materialForRole, using actual overrides. A Map avoids treating a user material name as an inherited object property. Counts exclude drawer boxes and are explicitly distinguished from manufacturing readiness.
- Draft base identity/params are retained when the model changes, so external edits cannot silently overwrite staged work. Reset explicitly loads current model state. Material/role/drawer signatures expire previews; mesh replacement does not. Apply guards live cabinet identity/params and uses a distinct history label.
- Twenty-one deliberate guard mutations produced expected assertion failures, covering finite/positive/non-negative and blank inputs, frame removal/layout retention, retained drawer configuration, stale cabinet identity/params, preview expiry, apply guards, invalid/no-op previews draft reset and the panel-material picker constraints. Each source was restored from a backup and compared before final validation. A multiline mutation replacement was corrected to match the formatted helper before executing the remaining cases.

- Final validation: all 196 unit-test files passed (3,469 tests passed, 10 skipped); all four Chromium workflows passed. Typecheck, lint, production build and catalogue service build passed. After the full run, the material-picker regression was extended to negative/non-finite stock; its three guards were separately mutated, restored and the focused tests passed again. No implementation changed after the full validation run.
