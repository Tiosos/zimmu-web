# Local change-review autosave

- 2026-10-15: Source comparison reviews use a separate IndexedDB database (`zimmu-review-drafts`, version 1). This avoids upgrading the project/handle database while it may be open elsewhere.
- Records contain only reviewer text and finding check-offs/notes, plus hashed comparison identity and timestamp. Source geometry stays in memory/project files. Both source hashes, release ID/revision/packet reference and a fingerprint of the complete recomputed comparison bind restoration to current rules.
- Writes are serialized and resolve on transaction completion. Reads await queued writes; pending writes continue after dialog unmount. Writing and pruning to ten recent records share a transaction. Clearing review fields saves an empty review, while opening an untouched review never overwrites an existing draft.
- Restore waits for storage and never replaces edits made while the read was pending. Save failures expose retry and retain the download/discard workflow. Closing waits for the latest draft; source/edit generations prevent delayed close from discarding newer changes.
- Local saves do not count as portable JSON checkpoints when importing another review. Existing overwrite confirmation still protects locally edited/restored notes. Simultaneous windows use last completed write; this is local persistence, not collaboration or authenticated approval.
- Browser storage can be cleared or evicted. JSON remains the portable backup. Packet-to-packet review persistence is separate and unchanged.
- Validation: 130 focused/integration tests across nine files passed, as did Chromium's real-project close/reopen, JSON-resume, report and undo workflow. Typecheck, lint and production build passed (existing bundle-size warnings remain). Mutation checks removing comparison fingerprint validation and the newer-edit restore guard each produced the expected assertion failure; both guards were restored and the regression suite passed again. An aborted IndexedDB write retains the previous committed draft.
