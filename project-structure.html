Zimmu — Project Structure

Open-core 3D joinery design app · Phase 0 web prototype

Last updated: 2026-06-13

Zimmu is a parametric 3D joinery design application for designers and architects who specify built woodwork — cabinetry, frame-and-panel, joinery — and need models that are buildable, dimensioned, and documentable without switching tools.

The current codebase is the browser prototype (Phase 0 / 0.5), validating the geometry seam, UX, and file format before a Rust/Tauri production shell is built. It runs entirely in the browser: OCCT geometry via WebAssembly, Comlink-bridged Web Worker, File System Access API for persistence.

Production target (Phase 1+)

OpenCASCADE · Rust/Tauri shell · Three.js + WebGPU · Custom .zmu format

Current prototype

opencascade.js (WASM) · Vite + React 19 · Three.js (WebGL) · .zimmu flat JSON

src/geom/ — Geometry kernel

OCCT bootstrap, tessellation, transforms, 2D drawing, STL/STEP export. No React imports. Browser-only (never call live OCCT in tests).

FileRole
occt.tsLazy singleton OCCT bootstrap. makeShape() (box + cut chain), makeTransformedShape(), writeStep() (XCAF named solids). Exports ExportSpec.
occt.worker.tsComlink Web Worker — exposes buildPart() and exportStep() to the main thread.
mesh.tsTopoDS_Shape → MeshData (Float32Arrays) + THREE.BufferGeometry via BRepMesh_IncrementalMesh.
transform.tscomposeWorldMatrix(part) — THREE-free world matrix. Single source of truth for part placement in STL/STEP export.
stl.tsbuildBinaryStl(parts, geometries) — world-space binary STL triangle soup with recomputed facet normals. Visible parts only.
drawing.tsbuildDrawingSheet(part) → DrawingView[]. Face/Edge/End orthographic projections with cut rects, dimension lines, cut labels.
dado.tsPure dado-joint geometry — isValidDadoSeat, deriveDadoAxes, computeDadoGroove, computeDadoSeat, computeRabbet, hasTongue, computeNotch (stopped/blind-dado housed-corner cut), and deriveJoint (the list of derived cuts + seat consumed by reconcileJoints). Three-typed but browser-free.
halflap.tsPure half-lap-joint geometry — worldAabb, stackAxis, isValidHalfLap (same stack axis + coincident thickness range + overlapping footprint), and deriveHalfLap (notches both boards to half thickness at the split plane, widened by clearance). Three-typed but browser-free.
mortisetenon.tsPure mortise-&-tenon-joint geometry — isValidMortiseTenon, computeTenonShoulders (0/2/4 shoulder cuts leaving a centered tongue), computeMortisePocket (blind or through pocket, axis-aligned to the tenon), computeMortiseOffset, and computeMortiseTenonSeat/deriveMortiseTenon. Self-contained (no runtime import from dado.ts). Three-typed but browser-free.
fingerjoint.tsPure box-&-finger-joint geometry — isValidFingerJoint, computeFingerCuts (world-parity-aware finger removal so mating slots interlock), computeFingerSeat, and deriveFingerJoint. Self-contained (no runtime import from dado.ts). Three-typed but browser-free.
tonguegroove.tsTongue & groove joint geometry (groove + centered tongue + edge seat).
occt.test.tsSmoke tests (live OCCT skipped in Node with it.skip).
transform.test.tsElement-wise parity tests against THREE.Matrix4.
stl.test.tsBinary STL output validation.
drawing.test.tsDrawing projection logic.

Data model

All canonical types live in src/scene/types.ts. The file format serializes a ZimmuFile to .zimmu (flat JSON).

// File format (FILE_FORMAT_VERSION = 2)
interface ZimmuFile {
  version: number       // must equal FILE_FORMAT_VERSION
  name: string
  appVersion: string
  units: 'mm'
  createdAt: string     // ISO 8601
  updatedAt: string
  camera: CameraState   // { position: Vec3, target: Vec3 }
  scene: Scene
}

interface Scene {
  parts: Part[]
  materials: Record<string, MaterialDef>  // keyed by material name
  hardware: HardwareItem[]
  joints: Joint[]       // first-class parametric joints (dado in v0.1)
}

// A joint owns the geometry it produces: a derived BoxCut on the housing
// board (tagged sourceJointId) plus the housed board's seated position.
// reconcileJoints() regenerates both from these fields.
interface DadoJoint {
  kind: 'dado'
  id: string            // "joint_"
  label: string
  housingPartId: PartId; housingFace: Face   // board + face carrying the groove
  housedPartId: PartId; housedEnd: Face      // board + end that seats in
  offset: number        // groove center along the housing narrow axis (mm)
  depth: number         // groove depth into the housing (mm)
  clearance: number     // added to groove width = housedThickness + clearance
  profile: 'plain' | 'rabbeted'   // NEW in JP2
  tongueThickness: number         // tongue/groove width when rabbeted
  rabbetFace: '+Z' | '-Z'         // housed thickness face the rabbet removes from
}
type Joint = DadoJoint

// The only Part kind in v0.1 (more kinds planned)
interface BoardPart {
  kind: 'board'
  id: PartId            // UUID string
  label: string
  length: number; width: number; thickness: number  // millimetres
  material: string      // "" = unspecified
  color: string         // hex e.g. "#d4a373"
  position: Vec3; rotation: Vec3                    // mm / degrees
  rotationOrder: 'XYZ'
  cuts: CutDef[]
  visible: boolean
}

interface CutDef {
  id: CutId
  label: string
  face: '+X' | '-X' | '+Y' | '-Y' | '+Z' | '-Z'
  position: Vec3; size: Vec3
  pairedCutId?: string  // "{partId}:{cutId}" — links to mating cut
  sourceJointId?: string  // set on derived cuts owned by a Joint (read-only in UI)
}

interface MaterialDef { costPerM2: number }

interface HardwareItem {
  id: string            // UUID
  name: string; qty: number; unit: string
  supplier: string; partNumber: string; unitCost: number
  notes: string
  linkedPartIds: string[]   // board part IDs this item is linked to
}

interface FaceHit {
  partId: PartId
  faceNormal: Vec3; faceCenter: Vec3
  localFaceNormal: Vec3; localHitPoint: Vec3
}

Key invariants

InvariantDetails
OCCT is browser-only Never call live OCCT APIs in tests. Guard with typeof window === 'undefined' or mock the module. Use it.skip for OCCT unit tests in Node.
Geometry layer boundary Geometry lives in src/geom/, rendering in src/render/. The viewport must not import OCCT directly.
Workers use Comlink expose() in the worker, wrap() in useScene. Lazy singleton so vi.stubGlobal('Worker', …) works in tests.
+Z up (CAD convention) Do not change camera.up.set(0, 0, 1) in the Viewport. All geometry math assumes +Z up.
shapeKey is the geometry cache key Encodes only shape-affecting fields: dimensions + cut positions/sizes. Adding a new shape-affecting field requires updating shapeKey() in src/scene/utils.ts.
ZimmuFile float precision Serialization rounds floats to 6 decimal places. FILE_FORMAT_VERSION = 2 in useFile.ts.
IDB schema bumps Bumping DB_VERSION in idb.ts requires adding the new store in onupgradeneeded. Current: v2 with handles + library.
Library vs. project materials scene.materials is per-file; library (IDB) is global. Merge at the BOM layer only. Never conflate in useScene.
rotationOrder is always 'XYZ' composeWorldMatrix in transform.ts hardcodes Euler XYZ. If you add another order, revisit it.
Visible parts only in exports STL, STEP, and DXF/SVG export skip parts where visible === false.

Code conventions

TypeScript

  • Strict mode + noUnusedLocals + noUnusedParameters
  • verbatimModuleSyntax on — use import type
  • No any. Explicit types over inference for non-trivial shapes.

React

  • Functional components only — no class components
  • Named exports preferred over default exports
  • No abstractions / error handling for impossible scenarios

Comments

  • Default: no comments
  • Only comment the why (hidden constraint, subtle invariant, workaround)
  • No docstrings. No multi-line comment blocks.

Changes

  • Surgical: touch only what you must
  • No speculative features or "future flexibility"
  • Match existing style even if you'd do it differently
