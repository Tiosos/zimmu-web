Zimmu — Project Structure

Open-core 3D joinery design app · Phase 0 web prototype

Last updated: 2026-06-13

Zimmu is a parametric 3D joinery design application for designers and architects who specify built woodwork — cabinetry, frame-and-panel, joinery — and need models that are buildable, dimensioned, and documentable without switching tools.

The current codebase is the browser prototype (Phase 0 / 0.5), validating the geometry seam, UX, and file format before a Rust/Tauri production shell is built. It runs entirely in the browser: OCCT geometry via WebAssembly, Comlink-bridged Web Worker, File System Access API for persistence.

Production target (Phase 1+)

OpenCASCADE · Rust/Tauri shell · Three.js + WebGPU · Custom .zmu format

Current prototype

opencascade.js (WASM) · Vite + React 19 · Three.js (WebGL) · .zimmu flat JSON

src/geom/ — Geometry kernel

OCCT bootstrap, tessellation, transforms, 2D drawing, STL/STEP export. No React imports. Browser-only (never call live OCCT in tests).

FileRole
occt.tsLazy singleton OCCT bootstrap. makeShape() (box + cut chain), makeTransformedShape(), writeStep() — an unnamed STEPControl_Writer compound of all solids in mm; the XCAF named-solid path is absent at runtime in opencascade.js v1.1.1. Exports ExportSpec.
occt.worker.tsComlink Web Worker — exposes buildPart() and exportStep() to the main thread.
mesh.tsTopoDS_Shape → MeshData (Float32Arrays) + THREE.BufferGeometry via BRepMesh_IncrementalMesh.
transform.tscomposeWorldMatrix(part) + resolveWorldMatrix(part, byId) (composes placement through ancestor components) + multiplyMatrix — THREE-free. resolveWorldMatrix is the single source of truth for part placement; equals composeWorldMatrix exactly for a top-level part.
stl.tsbuildBinaryStl(parts, geometries) — world-space binary STL triangle soup with recomputed facet normals. Visible parts only.
drawing.tsbuildDrawingSheet(part) → DrawingView[]. Face/Edge/End orthographic projections with cut rects, dimension lines, cut labels.
dado.tsPure dado-joint geometry — isValidDadoSeat, deriveDadoAxes, computeDadoGroove, computeDadoSeat, computeRabbet, hasTongue, computeNotch (stopped/blind-dado housed-corner cut), and deriveJoint (the list of derived cuts + seat consumed by reconcileJoints). Three-typed but browser-free.
halflap.tsPure half-lap-joint geometry — worldAabb, stackAxis, isValidHalfLap (same stack axis + coincident thickness range + overlapping footprint), and deriveHalfLap (notches both boards to half thickness at the split plane, widened by clearance). Three-typed but browser-free.
mortisetenon.tsPure mortise-&-tenon-joint geometry — isValidMortiseTenon, computeTenonShoulders (0/2/4 shoulder cuts leaving a centered tongue), computeMortisePocket (blind or through pocket, axis-aligned to the tenon), computeMortiseOffset, and computeMortiseTenonSeat/deriveMortiseTenon. Self-contained (no runtime import from dado.ts). Three-typed but browser-free.
fingerjoint.tsPure box-&-finger-joint geometry — isValidFingerJoint, computeFingerCuts (world-parity-aware finger removal so mating slots interlock), computeFingerSeat, and deriveFingerJoint. Self-contained (no runtime import from dado.ts). Three-typed but browser-free.
tonguegroove.tsTongue & groove joint geometry (groove + centered tongue + edge seat).
screw.tsPure screw-fixing geometry — deriveScrewJoint emits a clearance row through the housed panel and a pilot row into the housing, never both on one panel. The pilot depth is clamped rather than trusted: a screw that reaches the far face bursts out of it.
mitre.tsMitre geometry (flat and bevel).
dowelCut.tsDowel bore geometry.
occt.test.tsSmoke tests (live OCCT skipped in Node with it.skip).
transform.test.tsElement-wise parity tests against THREE.Matrix4.
stl.test.tsBinary STL output validation.
drawing.test.tsDrawing projection logic.

src/scene/ — Scene state & hooks

Single source of truth for all scene state. No Three.js imports (except snapMath.ts which uses THREE types only for testing convenience).

FileRole
types.tsCanonical types: ZimmuFile, Scene, Part/BoardPart, CutDef (incl. hole-array), MaterialDef, HardwareItem, Joint, Component, CarcaseParams, FaceHit, CameraState.
useScene.tsScene state + geometry lifecycle + undo/redo + exportStep + cut linking + materials/hardware CRUD + component/carcase CRUD + detach. Every mutation passes through applyPipeline (regenerateComponents → reconcileJoints). Lazy Comlink worker singleton.
useFile.tsFile System Access API save/open/new. Auto-reopen last file via IDB. isDirty tracking via JSON snapshot comparison.
idb.tsIndexedDB wrapper (schema v3) — three object stores: handles (FileSystemFileHandle), library (material cost rates and sheet stock) and settings (the global tool clearance).
utils.tsshapeKey(part) — geometry cache key. Encodes only shape-affecting fields (dimensions + cut positions/sizes).
snapMath.tsPure face/cut geometry math — faceAxes(), computeSnapDelta(). No React. Three-typed but browser-free.
fitCamera.tsPure camera framing for the Home key: worldBounds builds the world AABB of the visible parts, fitDirection preserves the current bearing, and fitCameraToParts solves the distance that satisfies both FOV half-angles.
useSnap.tsFace-to-face snap-align interaction state machine. Fed FaceHits from the raycaster.
useAddCut.tsClick-a-face-to-add-joinery-cut interaction state machine.
useAddJoint.tsTwo-click dado-joint creation state machine (housing face → housed end). Fed FaceHits from the raycaster.
useAddHalfLap.tsTwo-click half-lap-joint creation state machine (first board → overlapping second board). Fed FaceHits from the raycaster.
useAddMortiseTenon.tsTwo-click mortise-&-tenon-joint creation state machine (mortise face → perpendicular tenon end). Fed FaceHits from the raycaster.
useAddFingerJoint.tsTwo-click box/finger-joint creation state machine (one board's end → perpendicular equal-width end of another). Fed FaceHits from the raycaster.
useAddTongueGroove.tsTongue & groove two-click gesture.
useInteractionMode.tsCoordinator composing the seven gesture hooks (snap, cut, dado, half-lap, mortise-tenon, finger, tongue-groove) into one exclusive activeMode + normalized { onFaceClick, onFaceHover, sourceFace, hoveredFace, interactionActive, snapPhase } bundle for the viewport.
componentTree.tsPure tree helpers — componentsById, ancestorsOf, descendantIds, wouldCycle (reparent guard), promoteOrphans (a dangling parentId costs hierarchy, never parts). No React, no THREE.
carcaseRoles.tsPure CarcaseParams → ordered RoleSpec[] (role key, dims, local position/rotation) — the whole geometry of a carcase: sides, back, top/bottom, toe-kick or ladder base, the divisions the section tree resolves, the shelf-pin rows each opening asks for, and the loose shelves seated on them.
sectionTree.tsThe cabinet's interior division as a recursive tree: Section, InteriorSpec, resolveSections (tree → rectangles + division boxes), boundsOf (what encloses a section), validateSection. Pure.
sectionInterior.tssectionInteriors — every leaf that asks for shelving, with its rect and bounds. sectionOpenings lists every leaf whether shelved or not, setInterior writes one section's spec, and defaultInterior / seedInteriors / firstInterior serve the presets, the v16 migration and the legacy shim.
migrateSections.tslegacyToSection(dividers, fixedShelves, width, thickness) — the one place pre-v13 divider/shelf parameters become a tree. Needs width and thickness: a v12 divider is centred on a fraction of the gross width, a section percentage is a share of the clear span.
resolveThickness.tsroleThicknessFor(slots, materials, overrides) → (role) => thickness. The single statement of where a panel's thickness comes from: explicit override, else its own material, else the cabinet's slot for that role.
resolveJointKind.tsjointKindFor(joints, componentId) → (housingRole, housedRole) => kind. Its mirror for joinery, read before the layout resolves boxes, plus carcaseJointId — the one place a joint's deterministic id is spelled.
changeJointKind.tsConverts a joint between dado and screw, checking the pairing is legal. Only those two are convertible: the generator emits one or the other for identical role pairs.
cutOwnership.tsisJointOwned / isOwnedBy — the ownership question seven call sites ask, stated once. A copy that forgot a cut kind is how a stale bore survives its joint.
grain.tsThe grain convention in carcase axes (grainAxisOf) and its derivation into a board field (grainFieldFor). Deliberately fatal on an unknown role — a silent default would give a new family an arbitrary grain no test would notice.
defaultJoint.tsThe default parameters of each joint kind a cabinet emits.
useNest.tsDrives the nest worker for the Sheets tab: groups boards by nestable material and re-runs only when the job signature changes. enabled is held by the tab, so a six-cabinet nest never runs for a figure nobody is looking at.
regenerateComponents.tsPure Scene → Scene. Each carcase emits driven parts + driven joints, reconciled against existing parts by stable role key so ids survive and a driven: false part is never touched. Sibling of reconcileJoints; runs immediately before it.
carcasePresets.tsCARCASE_PRESETS — named parameter bundles (Base 600, Wall 600, Tall 600) and PRESET_MATERIALS. Data only. Base and Wall are one opening holding one adjustable shelf; Tall keeps four fixed shelves and seats none.
reconcileJoints.tsPure, idempotent regeneration of joint-derived groove cuts + seated positions from Scene.joints. Run after regenerateComponents, after every joint-affecting mutation, and on file load.
suggestJoints.tsSelection-driven joint suggestions: contactPair face + cornerPair corner detection + per-type validity → JointSuggestion[]; synthHit replays through existing onAdd* creators.
groupSuggestions.tsCollapses scene-wide suggestions to one PairGroup per board pair for the sidebar rows; orientationArrow disambiguates the two-orientation kinds. Does not cap — the row caps live in jointChecklist.ts.
jointChecklist.tsJoins touching pairs, scene.joints and suggestions into ChecklistRow[] — each pair jointed, open or no-offer — ordered by pair distance so a row keeps its slot when it flips to done. no-offer pairs are pruned by obbOverlap and capped by MAX_NOOFFER_ROWS.
obbOverlap.tsSeparating-axis overlap test on two boards' oriented boxes. Used by the checklist to drop AABB-only false positives (diagonal corner-kiss, rotated-board bounds) from the no-offer group.
useMaterialLibrary.tsLoads/persists material cost rates via the IDB library store.
palette.tsPART_COLORS preset swatches array.
useScene.test.ts, useFile.test.ts, etc.Co-located unit tests for each module.

src/nest/ — Sheet nesting

Bottom-left first-fit nesting onto stock sheets, run off-thread. A six-cabinet job is ~4.8 s, so it runs only while the Sheets tab is open.

FileRole
mask.tsoccupancyMask(part, clearance) — a 1 mm occupancy bitmask in board axes, dilated by half the clearance on every side and carrying its own pad. Never recompute the padding formula elsewhere.
nest.tsallowedRotations + rotateMask + nestSheets — bottom-left first fit, reporting placements, per-sheet utilisation and unplaced. Positions the dilated mask and reports the undilated rectangle.
nest.worker.tsComlink worker taking PARTS and masking them in the worker: a dilated mask for a 2100 mm panel is over a megabyte, so posting masks would transfer megabytes to save nothing.

src/render/ — Three.js viewport

FileRole
viewport.tsxReact-wrapped Three.js canvas. Manages meshes in refs (no React reconciliation over meshes). Per-part Mesh + LineSegments. Selection via emissive color. Raycaster emits FaceHit for snap/cut interactions.

src/ui/ — UI components

FileRole
FileMenu.tsxTop menu bar: File menu, project name, undo/redo buttons, BOM modal trigger, 3D/2D export buttons.
sidebar.tsxComposition shell: the SceneTree, the selected-node editor (EditPanel for a part, CarcasePanel for a carcase), and the Cut / Snap / joint mode buttons.
SceneTree.tsxSidebar hierarchy over components + parts: expand/collapse, selection, per-node visibility, driven/detached badges.

DimInput.tsxDimension number field with debounced commit, used across the edit and carcase panels.

DrawingViewer.tsxModal for 2D shop drawings. SVG preview; SVG + DXF download.

Data model

All canonical types live in src/scene/types.ts. The file format serializes a ZimmuFile to .zimmu (flat JSON).

// File format (FILE_FORMAT_VERSION = 16)
interface ZimmuFile {
  version: number       // must equal FILE_FORMAT_VERSION
  name: string
  appVersion: string
  units: 'mm'
  createdAt: string     // ISO 8601
  updatedAt: string
  camera: CameraState   // { position: Vec3, target: Vec3 }
  scene: Scene
}

interface Scene {
  parts: Part[]
  materials: Record<string, MaterialDef>  // keyed by material name
  hardware: HardwareItem[]
  joints: Joint[]        // first-class parametric joints (dado, half-lap, M&T, finger, T&G)
  components: Component[] // flat-stored nestable tree: 'group' | 'carcase' nodes, linked by parentId
}

// A component is a group or a parametric carcase. Carcases carry CarcaseParams;
// regenerateComponents(scene) turns those params into driven parts + driven joints,
// reconciling against existing parts by stable role key so a detached part survives.
interface Component {
  id: ComponentId        // "cmp_<uuid>"
  kind: 'group' | 'carcase'
  label: string
  parentId: ComponentId | null
  position: Vec3; rotation: Vec3; rotationOrder: 'XYZ'
  visible: boolean
  params?: CarcaseParams // present iff kind === 'carcase'
}

// A joint owns the geometry it produces: a derived BoxCut on the housing
// board (tagged sourceJointId) plus the housed board's seated position.
// reconcileJoints() regenerates both from these fields.
interface DadoJoint {
  kind: 'dado'
  id: string            // "joint_<uuid>"
  label: string
  housingPartId: PartId; housingFace: Face   // board + face carrying the groove
  housedPartId: PartId; housedEnd: Face      // board + end that seats in
  offset: number        // groove center along the housing narrow axis (mm)
  depth: number         // groove depth into the housing (mm)
  clearance: number     // added to groove width = housedThickness + clearance
  profile: 'plain' | 'rabbeted'   // NEW in JP2
  tongueThickness: number         // tongue/groove width when rabbeted
  rabbetFace: '+Z' | '-Z'         // housed thickness face the rabbet removes from
  driven: boolean; sourceComponentId?: string  // set on joints a carcase emits
}
// A screw fixing is the first joint whose geometry is bores rather than a groove: two
// hole arrays, never both on the same panel. It is also the cabinet default — and a
// screwed butt joint extends no panel, unlike a dado, which is why the layout has to
// read the joint kind *before* it resolves boxes.
interface ScrewJoint {
  kind: 'screw'
  id: string; label: string
  throughPartId: PartId; throughFace: Face      // clearance holes, right through
  receivingPartId: PartId; receivingEnd: Face   // pilots, blind and clamped
  screwCount: number; endInset: number
  clearanceDiameter: number; pilotDiameter: number; pilotDepth: number
  driven: boolean; sourceComponentId?: string
}

// Every joint interface adds { driven, sourceComponentId? }
type Joint = DadoJoint | HalfLapJoint | MortiseTenonJoint | FingerJoint
           | TongueGrooveJoint | ScrewJoint

interface BoardPart {
  kind: 'board'
  id: PartId            // UUID string
  label: string
  length: number; width: number; thickness: number  // millimetres
  grain: 'length' | 'width' | 'free'
  material: string      // "" = unspecified; the material states the thickness
  color: string         // hex e.g. "#d4a373"
  position: Vec3; rotation: Vec3                    // mm / degrees
  rotationOrder: 'XYZ'
  cuts: CutDef[]
  visible: boolean
  parentId: ComponentId | null  // owning component, or null when top-level
  driven: boolean               // true = emitted by a carcase; false = the user's, never touched
  role?: string                 // regeneration identity key, set only on driven parts
  overrides?: { thickness?: number; material?: string }  // read *before* the layout resolves boxes
}

// BoxCut is the boolean-subtract rectangle; 'hole-array' is the shelf-pin bore pattern
interface CutDef {         // = BoxCut | HoleArrayCut
  id: CutId
  label: string
  kind?: 'box' | 'hole-array'
  face: '+X' | '-X' | '+Y' | '-Y' | '+Z' | '-Z'
  position: Vec3; size: Vec3
  pairedCutId?: string    // "{partId}:{cutId}" — links to mating cut
  sourceJointId?: string  // set on derived cuts owned by a Joint (read-only in UI)
  sourceComponentId?: string  // set on cuts a component places directly (toe-kick notch, holes)
}

// The material is the authority on panel thickness: a part may override it, but nothing
// else states it. `sheet` absent means the material is not nested at all.
interface MaterialDef {
  costPerM2?: number    // areal rate for sheet/board stock
  costPerM?: number     // linear rate for round/linear stock (dowels)
  thickness?: number    // panel thickness in mm; required of a carcase or back slot
  sheet?: { length: number; width: number; costPerSheet?: number }
  hasGrain?: boolean    // absent = has grain, the safe default
}

// A cabinet's parameters. Its interior division — and the shelving inside it — is the
// section tree, not a set of scalars: splitting a section is what *creates* the
// partition or shelf between its children.
interface CarcaseParams {
  width: number; height: number; depth: number
  carcaseMaterial: string; backMaterial: string   // slots, each naming a MaterialDef
  hasTop: boolean
  backMode: 'captured' | 'applied' | 'none'
  baseMode: 'toe-kick' | 'ladder' | 'legs' | 'none'
  toeKickHeight: number; toeKickSetback: number
  section: Section
  jointMethod: 'dado-rabbet' | 'finger' | 'dowel' | 'butt-screw' | 'confirmat'
}

interface Section {
  id: SectionId          // "sec_<uuid>", never a path: an index would renumber siblings
  size: { kind: 'equal' } | { kind: 'fixed'; mm: number } | { kind: 'percent'; pct: number }
  content:
    | { kind: 'leaf' }
    | { kind: 'split'; axis: 'vertical' | 'horizontal'
        division: 'none' | 'panel' | 'rail'; children: Section[] }
  interior?: { adjustable: {
    shelves: number      // boards actually seated in this opening
    count: number        // pin positions per row — not a shelf count
    rows: 1 | 2; pitch: 32
    setback: number; backSetback: number
  } }
}

interface HardwareItem {
  id: string            // UUID
  name: string; qty: number; unit: string
  supplier: string; partNumber: string; unitCost: number
  notes: string
  linkedPartIds: string[]        // board part IDs this item is linked to
  linkedComponentIds: string[]   // cabinets/groups this item belongs to
}

interface FaceHit {
  partId: PartId
  faceNormal: Vec3; faceCenter: Vec3
  localFaceNormal: Vec3; localHitPoint: Vec3
}

Key invariants

InvariantDetails
OCCT is browser-only Never call live OCCT APIs in tests. Guard with typeof window === 'undefined' or mock the module. Use it.skip for OCCT unit tests in Node.
Geometry layer boundary Geometry lives in src/geom/, rendering in src/render/. The viewport must not import OCCT directly.
Workers use Comlink expose() in the worker, wrap() in useScene. Lazy singleton so vi.stubGlobal('Worker', …) works in tests.
+Z up (CAD convention) Do not change camera.up.set(0, 0, 1) in the Viewport. All geometry math assumes +Z up.
shapeKey is the geometry cache key Encodes only shape-affecting fields: dimensions + cut positions/sizes. Adding a new shape-affecting field requires updating shapeKey() in src/scene/utils.ts.
ZimmuFile float precision Serialization rounds floats to 6 decimal places. FILE_FORMAT_VERSION = 16 in useFile.ts (v11 added the component tree; v12 the carcase backSetback; v13 replaced dividers/fixedShelves with the section tree; v14 moved panel thickness onto the material; v15 added the screw joint kind; v16 moved adjustableShelves onto each section's interior). Unrelated to the IDB DB_VERSION, which is separately 3.
IDB schema bumps Bumping DB_VERSION in idb.ts requires adding the new store in onupgradeneeded. Current: v3 with handles + library + settings.
Library vs. project materials scene.materials is per-file; library (IDB) is global. Merge at the BOM layer only. Never conflate in useScene.
rotationOrder is always 'XYZ' composeWorldMatrix in transform.ts hardcodes Euler XYZ. If you add another order, revisit it.
Visible parts only in exports STL, STEP, and DXF/SVG export skip parts where visible === false.
Regeneration pipeline order is fixed regenerateComponents(scene) runs before reconcileJoints(scene), always, via applyPipeline in useScene.ts. Carcases emit parts and joints; reconcileJoints derives cuts and seats from those joints. Both stages are pure and idempotent.
A detached part is the user's driven: false means no regeneration and no deletion — a parameter change, a role disappearing, and deleting the whole component all preserve it.
The section tree is the only description of interior division dividers and fixedShelves are gone: splitting a section is what creates the partition or shelf between its children. A pre-v13 file is converted by legacyToSection at the parseFile boundary and nowhere else, so the generator never sees a legacy field.
Thickness comes from the material, and overrides are read before layout MaterialDef.thickness is the authority; roleThicknessFor states the whole rule once. The layout reads overrides before resolving boxes, never applies them after — a 25 mm side is what makes the bottom come out at W − 43 beside an 18 mm one. Overrides in, boxes out; an override must never depend on a generated dimension.
A cabinet is screwed together by default, and a screw extends no panel extensionFor returns 0 for screw; getting that wrong lengthens every housed panel silently. A per-joint override is read before the layout resolves boxes, exactly as a thickness override is — resolveJointKind.ts mirrors resolveThickness.ts. Sizing that followed the cabinet default while the joint followed the override left a 6 mm hole in the cabinet.
A joint-owned cut may be a box or a hole array Screw fixing is the first joint whose geometry is bores, so sourceJointId lives on HoleArrayCut too. cutOwnership.ts states the ownership question once; seven call sites ask it, and a copy that forgot a kind is how a stale bore survives its joint.
A pin row belongs to the section that needs it, not to the panel carcaseHoleArrays asks each section what it wants and contributes those rows to the panels bounding it, so a divider between a shelved bay and a drawer bank is bored on one face only. A row starts above its own section's floor; there is no absolute startHeight.
An adjustable shelf sits on a pin the cabinet actually bored pinRow(rect, spec) states the available pin positions once and both the row of bores and shelfPins read it. Shelves spread over the pin positions, not over the section's height: a ten-position row covers 288 mm of a 584 mm opening.
A loose shelf is joined to nothing and touches nothing SHELF_CLEARANCE holds it clear of both uprights and of the back — a contact the generator does not name is an unjoined pair on the joinery checklist forever. SHELF_FRONT_SETBACK is a separate figure for a separate reason: the front the cabinet will wear.
Shelving is edited per opening, and an opening is chosen by id sectionOpenings lists every leaf, shelved or not; setInterior writes one section's spec. CarcasePanel holds the pick by section id, never by index: the v12 divider shim rebuilds the tree with fresh ids on every keystroke, so an index would silently edit a different opening.
Grain is stated in carcase axes and derived into a board field grainAxisOf(role) names the direction; grainFieldFor turns it into 'length' or 'width' through the same map orientedPanel uses. Never assume grain runs along a panel's longer dimension — a 1200 × 400 wall unit's back runs it along the shorter one.
useFile.ts types base.params loosely tsc cannot see a file-format regression there: the parser compiles while producing objects that lack a required field, and the failure appears only when the generator dereferences it. Any change to CarcaseParams needs a parseFile test, not a green typecheck.
The nest runs off-thread, and only while the Sheets tab is open A six-cabinet job is ~4.8 s. BomModal drives useNest's enabled flag from its tab state and clears it on unmount. Masks are built in the worker, never posted to it.
resolveWorldMatrix is the single source of world placement For parentId: null it is byte-identical to composeWorldMatrix; never call composeWorldMatrix outside transform.ts. The one remaining mention elsewhere (in occt.ts) is a comment, not a call.

TypeScript

  • Strict mode + noUnusedLocals + noUnusedParameters

React

  • Functional components only — no class components
  • Named exports preferred over default exports
  • No abstractions / error handling for impossible scenarios

Comments

  • Default: no comments
  • Only comment the why (hidden constraint, subtle invariant, workaround)
  • No docstrings. No multi-line comment blocks.

Changes

  • Surgical: touch only what you must
  • No speculative features or "future flexibility"
  • Match existing style even if you'd do it differently

Projects are saved as .zimmu files — flat JSON, human-readable, floats rounded to 6 decimal places.

{
  "version": 16,
